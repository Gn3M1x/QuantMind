# QuantMind

个人智能量化金融研究实验室。第一阶段是本地运行的中文 ETF 研究工作台：选择 ETF → 获取真实历史日线 → 校验与 SQLite 缓存 → 确定性技术指标 → Plotly 图表 → Markdown 研究报告下载。

支持 `510300` 沪深300ETF、`510500` 中证500ETF、`159915` 创业板ETF。实现 MA5/20/60、Wilder RSI14、MACD(12,26,9)、20 日价格收益率、20 日年化历史波动率和所选区间最大回撤。本阶段没有策略回测、预测、多 Agent、证券账户或自动交易，无付费模型 API，无需密钥。

## 安装与启动

已在 Intel Mac、macOS 15.6.1、Python 3.11.17 验证。下载或克隆源码后先进入项目根目录（例如从其父目录运行 `cd QuantMind`）；以下命令均在项目根目录执行。

首次安装（已安装 Python 3.11）：

```bash
python3.11 -m venv .venv
.venv/bin/python --version
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

已有 Python 3.11 `.venv` 时直接复用，跳过创建环境这一步：

```bash
.venv/bin/python --version
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

访问 <http://127.0.0.1:8501>。按 `Ctrl+C` 停止。端口占用可加 `--server.port 8502`。

依赖版本固定在 `requirements.txt`，命令显式使用虚拟环境解释器，无需激活环境、升级全局 Python 或安装 Node 项目依赖。无需 API Key、`.env` 或 Streamlit secrets；`.env.example` 仅说明这一点。程序按需创建本地运行目录；首次打开工作台不请求行情，提交查询后才获取数据。服务默认只监听本机 `127.0.0.1`。

选择ETF、日期及数据源后点击「查询行情」；修改表单不会立即请求数据。可选自动、东方财富或新浪；单独指定来源时只查询该来源和该来源的真实缓存。「刷新行情」重新获取并更新缓存。结果标题始终显示实际已经提交的研究范围。报告页可预览并下载 UTF-8 Markdown。工作台按深色主题配置并验证。

## 数据来源、复权与单位

详见 [接口核对与单位说明](docs/data_contract.md)。主要接口 `AKShare fund_etf_hist_em`，上游东方财富 `push2his.eastmoney.com/api/qt/stock/kline/get`；请求 `period="daily"`、日期 `YYYYMMDD`、`adjust=""`。自动模式下失败后尝试 `AKShare fund_etf_hist_sina`，上游新浪 `finance.sina.com.cn/realstock/company/{sh或sz}{代码}/hisdata_klc2/klc_kl.js`，日期在返回后筛选。指定某个来源时只使用该来源，不自动切换。

分析使用单一来源。原始字段及来源元数据保持入库时的数值和声明，价量关系检查只用于一致性诊断。**展示层不再将历史元数据中的单位推断视为已核实。** 只有适配器同时提供 `volume_unit_verified` / `amount_unit_verified`、合法的 `*_unit_base` 和非空的 `*_unit_evidence`，才可显示万份、亿份、万元、亿元等物理单位量级。当前源字段定义存在缺省或文档冲突，未达到该条件时显示“亿原始单位（未核实）”等数量缩写；不猜测单位，不把展示转换写回数据库。报告也明确标出未核实。当前运行的价量检查不能替代上游字段定义或交易所原始数据字典。

统一**不复权**，收益为**价格收益率，不含现金分红，不是总收益率**。现金分红、拆分等事件可能导致价格跳变，影响技术指标、波动率和回撤。新浪接口没有复权参数；原始返回价格与510300的东财不复权抽样相符，但未独立核对全部权益事件。

## 缓存与刷新

- 数据库默认 `data/quantmind.sqlite3`；可通过环境变量 `QUANTMIND_DB_PATH` 改路径。
- `daily_bars` 主键为代码、交易日、来源、复权方式，代码是 TEXT。每行记录抓取时间；`fetch_batches` 记录接口、上游URL、版本、单位、请求/实际范围和行数。
- 每次加载起点之前730个自然日作预热，目标至少250条前置日线；不足时提示。仅在计算后裁剪展示区间。
- 已有真实缓存会重新校验。当天抓取、覆盖可用且查询结束早于今天时可以直接使用缓存。批次的实际首尾、请求范围、记录数量和长间隔决定是否尝试补取；不能只凭有几行就认为覆盖完整。
- 日期范围扩展、疑似缺口、跨天或手动刷新会请求完整预热及展示范围。一次成功响应按请求范围事务替换，包括更新已存在的行及删除上游已移除的行。超过10个自然日的间隔会触发再次请求，长假也可能触发，这是启发检查的保守取舍。
- 自动模式下东方财富失败后尝试新浪；两个接口每个有50秒进程级超时，合计等待可能约100秒。切换来源使用整段独立序列。可选接口均失败时返回通过校验的旧缓存，明确显示“使用缓存”、抓取时间及失败原因；无可用真实缓存明确失败。指定来源时仅尝试所选接口及其独立缓存，不读取其他来源的缓存。
- 本阶段不请求复权数据。存储层保留复权分区保护：将来接入复权时必须完整历史快照替换，不能追加混合不同批次的复权价格。

## 校验与指标口径

日期规范化、升序、重复检测，必需字段与数值类型、有限值、正价格、非负成交量/额及 OHLC 关系均在入库和分析前检查。严重异常阻止相应数据分析；零成交量或缺少可选成交额只提示。缺失 OHLC 不使用前向或零值填充。日志在 `logs/quantmind.log`，自动轮转。

无可靠交易日历。范围和新鲜度仅基于自然日启发：超过10天可能提示陈旧、上市前、长假、停牌或覆盖不足。周末、节假日不直接当缺失；不宣称严格验证交易日完整性。新鲜度相对于所选结束日检查，抓取时间和行情交易日期分别展示。当日数据可能尚未收盘或仍待上游更新。

| 指标 | 口径与最少样本 |
| --- | --- |
| MA5/20/60 | 收盘价简单平均，完整5/20/60个收盘价后输出 |
| RSI14 | 前14次变动正/负部分的简单平均作为初值，之后按 `(前值×13+当期)/14`；需15个收盘价。只有涨幅100，只有跌幅0，完全横盘50 |
| MACD | EMA以首收盘价初始化，α=2/(N+1)，递推12/26；第26个收盘价输出DIF；首有效DIF作为DEA初值，第9个有效DIF（第34个收盘价）起输出DEA。柱状值为 `2×(DIF−DEA)` |
| 20日价格收益率 | `close[t]/close[t-20]-1`，需21个收盘价，可能使用展示起点之前的预热数据 |
| 20日年化波动率 | 最近20个日简单收益率样本标准差，`ddof=1`，乘`√252`；需21个收盘价。252是假定的年交易日数 |
| 区间价格收益率 | 所选区间末价/首价−1，至少2条日线 |
| 区间最大回撤 | 所选区间内 `min(close/close.cummax()-1)`，至少2条，展示非正百分比 |

样本不足保留 NaN/None，顶部指标卡显示“—”并提示原因，其他指标说明及报告明确写“样本不足”；图表断开，不伪造为0。所有计算保留精度，显示时才格式化。EMA/RSI使用有限预热历史，结果仍可能受初始化影响，与其他软件采用不同起点或EMA初值时可能不同。界面与报告共享同一个 `Analysis` 和格式函数。

## 常见问题与已知限制

1. **东方财富报 RemoteDisconnected**：公开接口可能限制访问；自动模式会保留原因并尝试新浪，接口都失败才降级到真实缓存。指定来源时只尝试该源和其缓存。不要将失败理解为没有交易，不使用模拟行情替代。
2. **图表空段或样本不足**：起点前历史不足、上市较晚或短样本时属正常。扩大日期范围并不能保证数据源覆盖；查看来源与质量页。
3. **零成交量**：可能来自停牌或源站记录，保留并提示，未擅自认定或修复。指标使用已有收盘观测，不保证这些观测全部为有成交的交易日。
4. **日期区间空数据**：休市或上市前可能无数据。应用明确报空，不据此创造行情。日期跨越长假可能多次补取；没有严格交易日历去消除该歧义。
5. **刷新失败**：查看状态、数据截至日期和最后抓取时间。旧缓存的价格可能被上游修订，离线使用不能保证最新。
6. 这是历史统计工具，未加入现金分红再投资、费用、新闻、基本面或交易策略。技术观察线不构成确定性预测或投资建议。
7. 仅在当前 Intel Mac 和已固定依赖验证；其他操作系统、Python版本和公开源未来的字段变化需要重新验证。运行目录使用 `/data/`、`/reports/`、`/logs/`、`/output/` 根限定Git忽略规则；根目录的 SQLite/数据库旁文件、日志及浏览器输出也排除。`quantmind/` 源码和 `tests/` 人工 TEST 样本保留，不能强制添加本地运行产物。


## 交易日期与新版工作台

- 深色主题：背景 `#0B1220`，卡片 `#111827`，强调色 `#5B8DEF`；使用系统字体，红涨绿跌。
- 顶部5张核心卡片：最新日线收盘价、20日价格收益率、RSI14、年化波动率、区间最大回撤。“—”表示样本不足，随卡片及提示说明所需样本；下载报告仍明确写“样本不足”，数值使用同一结果。
- 550px主图按75%/25%分配K线与成交量，共享横轴；下方技术指标、历史行情、研究报告、数据说明四个标签页。
- 横轴是按真实记录升序构建的分类轴，每条已有记录占一个位置。不会对自然日reindex，不增加非交易日记录，不更改价格或补齐缺失值。
- 约三个月以内使用月日标签；更长区间标签含年份。Plotly按宽度与缩放自动控制刻度数量；悬停始终保留完整YYYY-MM-DD日期，K线、均线、成交量、RSI、MACD共享同一日期映射。
- 紧凑排列不是完整性认证。缺少可靠交易日历时，任何未返回日期均未被认定为休市。主图虚线标出超过3个自然日的记录间隔，数据说明的展开区域提供全部大于1个自然日的记录间隔，不判定其原因。
- 本轮修复与浏览器验收记录见 [docs/ui_revision.md](docs/ui_revision.md)。
