# K线横向边界

2026-10-16在现有Python 3.11虚拟环境实施，实际检查版本为Streamlit 1.66.0、Plotly Python 6.9.0、本地Plotly.js 3.7.0。复用局部Streamlit组件和同一个Analysis，不改变行情采集、指标、缓存或报告计算。没有执行Git commit或push。

## 实现

`quantmind/assets/chart/viewport.js` 的 `constrainRange(count, requested)` 是统一窗口入口。count只来自已提交区间的 `Analysis.frame`，不包含指标预热历史。分类轴仍是原始真实日期的记录序号；节假日不占槽位，悬停日期保留原值。

对N条记录：L=-0.5，R=N-0.5，W=min(N,max(1,请求宽度))，start=clamp(请求起点,L,R-W)，end=start+W。先保留宽度，再平移整个窗口；不会独立截断端点。两端仅半个记录槽位留白，足够显示完整蜡烛。缩小最多到全部记录，放大最少保留一个记录槽位，避免停在两根蜡烛之间的空隙。空数据返回null；无效范围回到全部记录；单根固定[-0.5,0.5]。

控制器的 `setRange` 将鼠标、底部时间轴平移、横向wheel、修饰键wheel/捏合、工具栏缩放、原生范围事件、恢复视图及sessionStorage恢复统一送入此函数；渲染时再次防御校验。合法横轴确定后才计算可见记录、中间K线与价格轴。快捷初始窗口的右侧范围改为N-0.5，不再额外延伸0.3槽位。

Pointer Events逐次处理水平位移，超出边界的位移立即消费；保持按下状态，在越界方向拖远后反向几像素也会立即移动。换窗口尺寸时使用当前绘图区像素宽度，不保留旧鼠标锚点。横向wheel每个事件也基于上一次合法范围，不累积边缘欠账；后续惯性输入沿用相同规则。

工具栏放大/缩小按钮在调用Plotly前先计算合法范围。Plotly的 `minallowed` / `maxallowed` 额外限制原生轴端缩放和框选预览；其自身逐端截断逻辑没有用于实现平移。[官方属性参考](https://plotly.com/javascript/reference/layout/xaxis/#layout-xaxis-minallowed)与[当前版本范围处理源码](https://github.com/plotly/plotly.js/blob/v3.7.0/src/plots/cartesian/set_convert.js)已经核对。

原有约30fps串行绘制、最新输入优先、松手/惯性结束校准、内部relayout重入保护、监听器解绑和清理继续使用。每次原子更新所有共享横轴与主图价格轴。主图仍以中间K线的(high+low)/2居中；可见影线和显示均线决定对称半幅。成交量、MACD和RSI保留各自尺度。

普通界面操作保留位置；新ETF、日期或重新查询生成新query UUID，按新记录重建范围。浏览器手势不发组件控件值，不访问行情接口，不触发Python页面重跑。所有JS与Plotly资源随源码分发，不增加CDN或前端构建要求。

## 人工Mac触控板验收

1. 在 `http://127.0.0.1:8501` 查询真实ETF行情，选择1个月或3个月，保持自动跟随开启。
2. 将指针放在主图或副图，用双指连续左右滑至最早/最新记录，边缘应立即停止，最边缘蜡烛完整显示，不能出现大片数据外空白。
3. 到边缘后继续同向滑动，再小幅反向。反向应立即移动，没有先滑回一段才响应的空走距离。
4. 快速甩动后抬手，检查惯性期间仍不越界、不回弹、不挤压蜡烛；反向操作应立即有效。
5. 物理捏合放大后再滑到两端，继续缩小直到全部数据；查看K线密度、主副图日期以及中心影线中点的垂直位置。图表外上下滑动应正常滚动页面。
6. 改ETF、缩短日期并提交查询，再重复边界检查；普通均线、副图和标签页切换应保留位置。关闭跟随后允许手动纵轴，恢复视图重新开启跟随。

实体Mac双指手势、硬件惯性与物理捏合手感尚需人工确认；自动化发送的是浏览器wheel事件序列。Safari、Firefox和实体手机也未验证。
